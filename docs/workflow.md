# Правила работы с ветками и коммитами

## Ветки

* Ветка `main` является основной. Прямые коммиты в `main` запрещены.
* Любое изменение выполняется в отдельной ветке и попадает в `main` через Pull Request.
* Формат имени ветки: `type/short-topic`, где `type` принимает значения:
    * `feature` — новая функциональность;
    * `fix` — исправление ошибок;
    * `docs` — документация;
    * `chore` — рутинные задачи;
    * `test` — тесты.
* Примеры: `docs/workflow-rules`, `feature/add-parser`, `fix/date-format`.

## Коммиты

* Один коммит фиксирует одну законченную мысль.
* Сообщение коммита задаётся в формате `<type>: <действие>`, где `<type>` принимает значения:
    * `feat` — новая функция;
    * `fix` — исправление;
    * `docs` — изменения в документации;
    * `chore` — рутинные задачи;
    * `test` — добавление/исправление тестов;
    * `refactor` — рефакторинг кода.
* Примеры: `docs: add workflow rules`, `feat: add app entrypoint`, `chore: add gitignore`.

## Pull Request

* В описании указываются: цель изменения, что сделано и как проверить.
* Pull Request должен проходить локальные проверки:
    * `ruff check .`
    * Запуск проекта: `python src/app.py`
* Если добавлены тесты, они должны запускаться командой `pytest`.
