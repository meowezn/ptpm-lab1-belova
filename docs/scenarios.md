## 1. Роли

- **Пользователь** — студент, работающий со своими задачами.
- **Система** — модуль «Сервис задач», выполняющий операции, валидацию и работу с JSON.

## 2. Сценарии

### S-01. Создание задачи
**Приоритет:** критический

**Цель:** создать новую задачу.

**Условия:** количество задач меньше 10 000; хранилище доступно.

**Шаги:**
1. Пользователь вводит название.
2. Пользователь вводит описание.
3. Пользователь подтверждает создание.
4. Система проверяет название.
5. Система создаёт задачу.

**Ожидаемый результат:** задача появляется в списке, получает уникальный ID и статус `new`; после сохранения присутствует в JSON.

### S-02. Просмотр списка задач
**Приоритет:** критический

**Цель:** просмотреть существующие задачи.

**Условия:** в хранилище есть задачи.

**Шаги:**
1. Пользователь запрашивает список.
2. Система возвращает список.

**Ожидаемый результат:** отображаются все существующие задачи с ID, названием, описанием и статусом.

### S-03. Изменение статуса
**Приоритет:** критический

**Цель:** изменить статус существующей задачи.

**Условия:** задача существует.

**Шаги:**
1. Пользователь выбирает задачу по ID.
2. Пользователь устанавливает `in_progress`.
3. Система проверяет значение.
4. Система изменяет статус.
5. Система сохраняет изменения.

**Ожидаемый результат:** статус изменён, ID не изменился, новое состояние сохранено.

### S-04. Поиск по ключевому слову
**Приоритет:** важный

**Цель:** найти нужные задачи.

**Условия:** есть задачи с ключевым словом в названии или описании.

**Шаги:**
1. Пользователь вводит ключевое слово.
2. Система ищет его в названии и описании без учёта регистра.
3. Система возвращает результаты.

**Ожидаемый результат:** возвращены только задачи, содержащие ключевое слово.

### S-05. Загрузка задач при старте
**Приоритет:** критический

**Цель:** восстановить ранее сохранённые задачи.

**Условия:** JSON-файл корректен.

**Шаги:**
1. Пользователь запускает модуль.
2. Система читает JSON.
3. Система проверяет структуру.
4. Система загружает задачи.

**Ожидаемый результат:** восстановлены те же ID, названия, описания и статусы.

### S-06. Отсутствие файла данных
**Приоритет:** важный

**Цель:** начать работу без существующего файла.

**Условия:** JSON-файл отсутствует.

**Шаги:**
1. Пользователь запускает модуль.
2. Система обнаруживает отсутствие файла.
3. Система инициализирует пустое хранилище.
4. Пользователь запрашивает список.

**Ожидаемый результат:** аварийного завершения нет, возвращается пустой список; при последующем сохранении создаётся файл.

### S-07. Повреждённый JSON
**Приоритет:** важный

**Цель:** безопасно обработать повреждённое хранилище.

**Условия:** файл содержит некорректный JSON или несовместимую структуру.

**Шаги:**
1. Пользователь запускает модуль.
2. Система читает файл.
3. Система обнаруживает ошибку формата.
4. Система возвращает `DataFileCorrupted`.

**Ожидаемый результат:** загрузка не считается успешной, понятная ошибка возвращена, исходный файл не перезаписан автоматически.

### S-08. Недопустимый статус
**Приоритет:** важный

**Цель:** предотвратить установку неизвестного статуса.

**Условия:** задача существует.

**Шаги:**
1. Пользователь выбирает задачу.
2. Пользователь передаёт `cancelled`.
3. Система проверяет допустимые значения.
4. Система отклоняет операцию.

**Ожидаемый результат:** возвращается `InvalidStatus`, прежний статус сохраняется.

### S-09. Пустое название
**Приоритет:** важный

**Цель:** предотвратить создание некорректной задачи.

**Условия:** лимит не достигнут.

**Шаги:**
1. Пользователь оставляет название пустым или вводит пробелы.
2. Пользователь подтверждает создание.
3. Система выполняет валидацию.
4. Система отклоняет создание.

**Ожидаемый результат:** возвращается `EmptyTitle`, новая задача не появляется и данные не изменяются.

### S-10. Изменение названия и описания
**Приоритет:** важный

**Цель:** актуализировать данные задачи.

**Условия:** задача существует.

**Шаги:**
1. Пользователь выбирает задачу.
2. Пользователь вводит новое название.
3. Пользователь вводит новое описание.
4. Система проверяет название.
5. Система сохраняет изменения.

**Ожидаемый результат:** название и описание обновлены; ID и статус прежние.

### S-11. Поиск без совпадений
**Приоритет:** дополнительный

**Цель:** обработать пустой результат поиска.

**Условия:** ключевого слова нет ни в одном названии или описании.

**Шаги:**
1. Пользователь вводит отсутствующее слово.
2. Система выполняет поиск.

**Ожидаемый результат:** возвращается пустой список без ошибки.

### S-12. Несуществующий ID
**Приоритет:** важный

**Цель:** корректно обработать обращение к отсутствующей задаче.

**Условия:** указанного ID нет.

**Шаги:**
1. Пользователь передаёт неизвестный ID.
2. Система выполняет поиск.
3. Система не находит задачу.

**Ожидаемый результат:** возвращается `TaskNotFound`, существующие данные не изменяются.

### S-13. Превышение лимита
**Приоритет:** дополнительный

**Цель:** проверить ограничение количества задач.

**Условия:** уже существует 10 000 задач.

**Шаги:**
1. Пользователь пытается создать ещё одну задачу.
2. Система проверяет лимит.
3. Система отклоняет создание.

**Ожидаемый результат:** возвращается `TaskLimitExceeded`, количество задач остаётся 10 000.
