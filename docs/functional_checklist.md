## 1. Граница проверки

Чек-лист проверяет функциональность создания, просмотра, изменения, поиска, загрузки и сохранения задач, а также обработку типовых ошибочных ситуаций.

**BLOCK** — при провале пункта релиз или сдача запрещены до исправления дефекта или официального разрешения преподавателя.

**WARN** — дефект должен быть зафиксирован; сдача возможна только если он не является критичным и явно отмечен.

## 3. Минимальный регрессионный набор

Если времени недостаточно, обязательными для повторного прогона являются все пункты `BLOCK`:

`CL-01, CL-02, CL-03, CL-05, CL-06, CL-07, CL-09, CL-10, CL-11, CL-12, CL-13, CL-14`.

Они покрывают создание, просмотр, изменение, поиск, сохранение, восстановление и ключевые ошибочные ситуации.

## 4. Данные для проверки

### 4.1. Тестовые задачи

**TD-01 — короткая**
- Название: `Купить тетрадь`
- Описание: `Подготовка к занятиям`
- Статус после создания: `new`

**TD-02 — длинное описание**
- Название: `Подготовить лабораторную`
- Описание: `Оформить требования, пользовательские сценарии, чек-лист и проверить результаты перед сдачей`
- Статус после создания: `new`

**TD-03 — смешанный регистр**
- Название: `Изучить Python`
- Описание: `Повторить работу с JSON и файлами`
- Статус после создания: `new`

**TD-04 — ключевое слово в описании**
- Название: `Подготовка проекта`
- Описание: `Проверить сохранение данных в JSON`
- Статус после создания: `new`

### 4.2. Ошибочные данные

**ED-01 — пустое название**
- Название: `""`
- Описание: `Проверка валидации`
- Ожидается: `EmptyTitle`

Дополнительный вариант:
- Название: `"   "`
- Ожидается: `EmptyTitle`

**ED-02 — недопустимый статус**
- ID: существующий ID из TD-01
- Статус: `cancelled`
- Ожидается: `InvalidStatus`, статус TD-01 не меняется.

### 4.3. Данные для повреждённого файла

Для отдельной проверки создать копию JSON и заменить содержимое на:

```text
{"tasks": [
```

Ожидается: `DataFileCorrupted`, автоматической перезаписи повреждённого файла нет.

## 6. Задание для закрепления: риск-мышление

### CL-10 — восстановление после перезапуска
**Частый дефект:** данные сохраняются не полностью или не загружаются после повторного запуска.  
**Почему опасен:** пользователь теряет ранее созданные задачи, поэтому основная функция постоянного хранения становится неработоспособной.

### CL-12 — повреждённый JSON
**Частый дефект:** модуль аварийно завершается или перезаписывает исходный файл при ошибке чтения.  
**Почему опасен:** можно потерять сохранённые данные и получить неконтролируемое поведение при следующем запуске.

## 7. Самопроверка чек-листа

- 17 пунктов, рассчитанных на короткий повторяемый прогон.
- Каждый пункт связан с минимум одним R-xx и S-xx.
- Есть штатные и ошибочные проверки.
- Есть сохранение, восстановление, отсутствующий и повреждённый JSON.
- Есть пустое название и недопустимый статус.
- Использованы фиксированные тестовые данные.
- `BLOCK` определён как запрет выпуска/сдачи при провале.
