## 3. Тест-кейсы

### TC-01 — Создание задачи с валидными полями
**Идентификатор:** TC-01  
**Название:** Создание задачи с валидными полями  
**Связь:** R-01, R-02, R-03; S-01  
**Предусловия:** модуль запущен; в хранилище менее 10 000 задач; JSON доступен для записи.  
**Входные данные:** название `Smoke`; описание `Release`.  
**Шаги:**
1. Передать название и описание.
2. Создать задачу.
3. Получить её по ID.
4. Получить список.
**Ожидаемый результат:** задача создана, ID непустой и уникальный, поля сохранены, статус `new`, задача есть в списке.  
**Постусловия:** задача A сохранена.  
**Важность:** BLOCK

**Как этот тест-кейс защитит от регрессии:** обнаружит поломку создания, обязательных полей, ID или начального статуса.

### TC-02 — Создание задачи с пустым названием
**Идентификатор:** TC-02  
**Название:** Отклонение задачи с пустым названием  
**Связь:** R-01; S-09  
**Предусловия:** модуль запущен; лимит не достигнут.  
**Входные данные:** название `""`; описание `Проверка валидации`.  
**Шаги:** передать данные и выполнить создание.  
**Ожидаемый результат:** возвращается `EmptyTitle`; задача не создаётся; существующие данные не меняются.  
**Постусловия:** количество задач не изменилось.  
**Важность:** BLOCK

### TC-03 — Просмотр списка после создания
**Идентификатор:** TC-03  
**Название:** Отображение созданных задач в списке  
**Связь:** R-05; S-02  
**Предусловия:** модуль запущен.  
**Входные данные:** A `Smoke`/`Release`; B `Отчёт по практике`/длинное описание.  
**Шаги:** создать A и B; запросить список; найти обе задачи по ID.  
**Ожидаемый результат:** обе задачи присутствуют с ID, названием, описанием и статусом.  
**Постусловия:** A и B остаются в хранилище.  
**Важность:** BLOCK

### TC-04 — Изменение статуса на допустимый
**Идентификатор:** TC-04  
**Название:** Установка статуса `in_progress`  
**Связь:** R-08, R-17; S-03  
**Предусловия:** задача A существует со статусом `new`.  
**Входные данные:** ID A; статус `in_progress`.  
**Шаги:** передать ID и статус; выполнить изменение; получить задачу.  
**Ожидаемый результат:** статус `in_progress`; ID не изменился.  
**Постусловия:** A имеет `in_progress`.  
**Важность:** BLOCK

### TC-05 — Изменение статуса на недопустимый
**Идентификатор:** TC-05  
**Название:** Отклонение статуса `cancelled`  
**Связь:** R-08; S-08  
**Предусловия:** задача A существует.  
**Входные данные:** ID A; статус `cancelled`.

**Постусловия:** данные задачи не изменены.  
**Важность:** BLOCK

### TC-06 — Поиск без учёта регистра
**Идентификатор:** TC-06

**Предусловия:** существует C с `PyTest Case`; есть задача с `JSON` в описании.  
**Входные данные:** `pytest`, `PYTEST`, `json`, `JSON`.  
**Шаги:** выполнить поиск каждой пары и сравнить результаты.  
**Ожидаемый результат:** результаты для разных регистров совпадают; поиск работает по названию и описанию.  
**Постусловия:** задачи не изменены.  
**Важность:** BLOCK

### TC-07 — Поиск без совпадений

**Название:** Поиск отсутствующего слова  
**Связь:** R-12; S-11

**Входные данные:** `xyz_nonexistent`.  
**Шаги:** выполнить поиск.  
**Ожидаемый результат:** пустой список без ошибки.  
**Постусловия:** хранилище не изменилось.  
**Важность:** WARN

### TC-08 — Сохранение в JSON
**Идентификатор:** TC-08  
**Название:** Сохранение актуального состояния  
**Связь:** R-13; S-01  
**Предусловия:** JSON доступен для записи.  
**Входные данные:** A `Smoke`/`Release`/`new`.  
**Шаги:** создать A; сохранить; открыть JSON; найти A по ID.  
**Ожидаемый результат:** файл записан без ошибки; есть `tasks`; запись содержит `id`, `title`, `description`, `status` с актуальными значениями.  
**Постусловия:** JSON содержит актуальное состояние.  
**Важность:** BLOCK

**Как этот тест-кейс защитит от регрессии:** покажет потерю полей или изменение формата JSON после рефакторинга.

### TC-09 — Восстановление после перезапуска
**Идентификатор:** TC-09  
**Название:** Загрузка сохранённых задач  
**Связь:** R-14, R-18; S-05  
**Предусловия:** JSON содержит сохранённую A.  
**Входные данные:** существующий корректный JSON.  
**Шаги:** запустить модуль; дождаться загрузки; получить список; найти A.  
**Ожидаемый результат:** ID, название, описание и статус A восстановлены без изменений.  
**Постусловия:** данные доступны для дальнейших операций.  
**Важность:** BLOCK

**Как этот тест-кейс защитит от регрессии:** обнаружит поломку чтения JSON и потерю данных после перезапуска.

### TC-10 — Первый запуск без файла
**Идентификатор:** TC-10  
**Название:** Работа при отсутствии JSON-файла  
**Связь:** R-15; S-06  
**Предусловия:** JSON-файл отсутствует; каталог доступен для записи.  
**Входные данные:** отсутствующий файл.  
**Шаги:** убедиться, что файла нет; запустить модуль; получить список; создать A; сохранить.  
**Ожидаемый результат:** аварийного завершения нет; до создания список пуст; после сохранения файл создан и содержит A.  
**Постусловия:** создан корректный JSON.  
**Важность:** BLOCK

### TC-11 — Повреждённый JSON
**Идентификатор:** TC-11  
**Название:** Диагностика повреждённого JSON  
**Связь:** R-14; S-07  
**Предусловия:** JSON содержит некорректные данные; есть резервная копия.  
**Входные данные:** `{"tasks": [`  
**Шаги:** записать данные в файл; запустить модуль; проверить результат и исходный файл.  
**Ожидаемый результат:** `DataFileCorrupted`; загрузка неуспешна; исходный файл не перезаписан автоматически.  
**Постусловия:** повреждённый файл сохранён для диагностики.  
**Важность:** BLOCK

### TC-12 — Проверка JSON-контракта
**Идентификатор:** TC-12  
**Название:** Проверка структуры записи задачи  
**Связь:** R-13; S-05  
**Предусловия:** есть корректный JSON.  
**Входные данные:**
```json
{
  "tasks": [
    {
      "id": "1",
      "title": "Smoke",
      "description": "Release",
      "status": "new"
    }
  ]
}
```
**Шаги:** проверить `tasks`; проверить массив; проверить поля `id`, `title`, `description`, `status`; проверить типы и допустимый статус.  
**Ожидаемый результат:** структура соответствует контракту; обязательные поля и типы корректны.  
**Постусловия:** файл не изменён.  
**Важность:** WARN

### TC-13 — Несуществующий ID
**Идентификатор:** TC-13

**Связь:** R-04; S-12

**Входные данные:** `999999`.  
**Шаги:** выполнить получение или изменение задачи по ID.  
**Ожидаемый результат:** `TaskNotFound`; существующие данные не изменились.  
**Постусловия:** хранилище без изменений.  
**Важность:** WARN

### TC-14 — Изменение названия и описания
**Идентификатор:** TC-14  
**Название:** Обновление текста задачи  
**Связь:** R-06, R-07, R-17; S-10  
**Предусловия:** A существует.  
**Входные данные:** новое название `Smoke Updated`; новое описание `Release Updated`.  
**Шаги:** запомнить ID и статус; изменить название; изменить описание; получить A.  
**Ожидаемый результат:** текст обновлён; ID и статус прежние.  
**Постусловия:** обновлённые данные готовы к сохранению.  
**Важность:** WARN

### TC-15 — Лимит 10 000 задач
**Идентификатор:** TC-15  
**Название:** Проверка граничного значения лимита  
**Связь:** R-16; S-13  
**Предусловия:** существует 9 999 задач; хранилище доступно.  
**Входные данные:** `Limit Test 10000` и `Limit Test 10001`.  
**Шаги:** создать 10 000-ю; проверить количество; попытаться создать 10 001-ю; проверить количество.  
**Ожидаемый результат:** 10 000-я создаётся; 10 001-я отклоняется с `TaskLimitExceeded`; всего остаётся 10 000 задач.  
**Постусловия:** лимит не превышен.  
**Важность:** WARN
